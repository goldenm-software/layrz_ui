# LayrzAiMarker — API Reference

Source: `lib/src/ai_marker/src/ai_marker.dart`
- `LayrzAiMarker` class (`StatefulWidget`) + `LayrzAiMarker.wrap` static method
- `lib/src/ai_marker/src/ai_marker_wrapper.dart` — `LayrzAiMarkerWrapper`
- `lib/src/ai_marker/src/ai_marker_position.dart` — `LayrzAiMarkerPosition` enum

---

## Examples

```dart
// Standalone
const LayrzAiMarker()

// Overlaid on the top-right corner (default position)
LayrzAiMarker.wrap(
  child: LayrzCard(child: Text('This summary was written by AI.')),
)

// Overlaid on the bottom-left corner
LayrzAiMarker.wrap(
  position: LayrzAiMarkerPosition.bottomLeft,
  child: const AvatarThumbnail(),
)

// Toggling visibility based on content origin
LayrzAiMarker.wrap(
  isVisible: message.isAiGenerated,
  child: MessageCard(message: message),
)

// Using LayrzAiMarkerWrapper directly (equivalent to LayrzAiMarker.wrap)
LayrzAiMarkerWrapper(
  position: LayrzAiMarkerPosition.topRight,
  child: const SummaryCard(),
)
```

## Constructor

```dart
@immutable
class LayrzAiMarker extends StatefulWidget {
  const LayrzAiMarker({super.key});

  static Widget wrap({
    Key? key,
    required Widget child,
    LayrzAiMarkerPosition position = LayrzAiMarkerPosition.topRight,
    bool isVisible = true,
  });
}
```

`LayrzAiMarker` itself takes only `key` — no `size`, no `text`/`label`/`tooltip` override.

## Properties

### `LayrzAiMarker`

| Property | Type | Default | Notes |
|---|---|---|---|
| `key` | `Key?` | `null` | Standard widget key. No other constructor parameters exist. |

### `LayrzAiMarker.wrap` (static method) / `LayrzAiMarkerWrapper`

| Property | Type | Default | Notes |
|---|---|---|---|
| `child` | `Widget` | required | The widget the marker overlays. Never affects `child`'s layout size — painted on top via `Positioned`/`FractionalTranslation`. |
| `position` | `LayrzAiMarkerPosition` | `.topRight` | Which corner of `child` the marker anchors to. |
| `isVisible` | `bool` | `true` | When `false`, only `child` renders — no marker visual, no overlay, no disclosure semantics attached. Toggle based on whether the content is actually AI-generated while keeping the tree stable. |
| `key` | `Key?` | `null` | Standard widget key. |

There is no `semanticsLabel`/`tooltip` parameter on either the widget or the wrapper — see the class doc for why.

---

## `LayrzAiMarkerPosition` enum

| Value | Description |
|---|---|
| `.topRight` (default) | Anchors the marker to the top-right corner. The conventional default for a card or bubble. |
| `.topLeft` | Anchors to the top-left corner. |
| `.bottomRight` | Anchors to the bottom-right corner. |
| `.bottomLeft` | Anchors to the bottom-left corner. |

Names the four corners rather than exposing raw `Alignment` arithmetic, mirroring `LayrzBadgeAlignment`'s naming.

## Companion widgets

- **`LayrzAiMarkerWrapper`** (`lib/src/ai_marker/src/ai_marker_wrapper.dart`) — the `StatelessWidget` `LayrzAiMarker.wrap` delegates to. Independently constructible; use it directly if preferred over the static method. Same parameters as `.wrap` (`child`, `position`, `isVisible`, `key`).

## Behavior notes

- **Disclosure text is not configurable, anywhere.** Both `Semantics.label` (`LayrzUiL10n.aiGeneratedLabel`, default `"Generated by AI"`) and the `LayrzTooltip` content (`LayrzUiL10n.aiGeneratedTooltip`, same default) come exclusively from `LayrzUiL10n.of(context)`. This is intentional: the disclosure must read identically, and be translated identically, everywhere the marker is used — a per-call-site override would let two places disclose the same fact in different strings or let one drift out of translation. Localize via a `LayrzUiL10n` subclass in the `l10n` module.
- **Fixed 30×30 footprint.** The container renders at one hand-tuned size everywhere; there is no `size` parameter and none is planned. Each star glyph's placement and size are internal-only tuning knobs, never public API.
- **Two independent animations.** A staggered star-burst "twinkle" (each star pops in with a scale bounce, phase-offset from the other, settling between repeats — never a rotation, so it never reads as a loading spinner) and a slow ~4-second glow orbit (a soft `BoxShadow` sweeping around the container's edge). They run on separate `AnimationController`s so neither drags the other's pace.
- **Reduced motion.** Both animations switch off entirely under `MediaQuery.disableAnimationsOf(context)` — stars render in their settled resting pose, the glow becomes a fixed, non-orbiting shadow. This is non-negotiable: both effects are vestibular triggers.
- **Accessibility is the whole point.** Never colour-alone — the mandatory `Semantics` label and `LayrzTooltip` are always present; there is no way to construct a `LayrzAiMarker` without them.
- **`.wrap` semantics differ from `LayrzBadge`.** A badge count is meaningless without the icon it decorates, so `LayrzBadge` merges/excludes semantics; `LayrzAiMarker.wrap` does not — AI disclosure and the child's own content are two independent facts a screen reader user needs to hear separately.
